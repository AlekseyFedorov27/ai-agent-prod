# Что изменено и как обновиться

## Как применить

1. Скопируйте содержимое архива поверх проекта (структура папок совпадает).
2. Удалите устаревшие файлы (список ниже).
3. Создайте `.env` из нового `.env.example` (появились обязательные `API_KEY`, `LANGFUSE_NEXTAUTH_SECRET`, `LANGFUSE_SALT`; в `POSTGRES_URI` и `REDIS_URI` теперь имена сервисов `postgres` и `redis`).
4. Пересоздайте таблицу чанков (размерность эмбеддингов изменилась) и пересоберите контейнеры:

```bash
docker exec -it agent_postgres psql -U postgres -d langgraph_db -c "DROP TABLE IF EXISTS document_chunks;"
docker compose up -d --build
```

5. Загрузите документы заново (`examples/omega.txt` для проверки).

## Удалить

- `uploads/test.txt` и `uploads/test.txt.txt`: тестовый документ перенесён в `examples/omega.txt`, дубль не нужен.
- `payload.json` и `print.py` из репозитория (они в `.gitignore`; если уже попали в git: `git rm --cached payload.json print.py`).
- Папку `uploads/` из git, если она отслеживалась: `git rm -r --cached uploads`.

## Важное про версии

SDK Langfuse v2 не совместим с langchain 1.x (проверено при установке). Поэтому стек зафиксирован на langchain 0.3 и langgraph 0.6: там есть `interrupt()` и `Command`, а Langfuse v2 работает. При переходе на Deep Agents (требует langchain 1.x) придётся выбрать: Langfuse v3 с новым сервером или другая трассировка.

## Что проверено, а что нет

Проверено: 47 автотестов (загрузка и очистка имён, HITL во всех вариантах, стриминг и возобновление через API, лимит запросов, конфигурация), линтер ruff; на реальном PostgreSQL 16 проверено, что пауза на подтверждении сохраняется в чекпоинтере и решение применяется после «перезапуска» (новое соединение и новый граф).

Не проверено (в среде не было): сборка Docker-образа и `docker compose up`, расширение pgvector и поиск по векторам, загрузка модели fastembed, реальная LLM и Langfuse, Python 3.11 (тесты прогонялись на 3.13). Начните с `docker compose up` и проверки по README.
